## 1. 现状审计（2026-09-02，以代码为准）

### 1.1 已具备（不重建，只增强）

- 产品闭环骨架：登录/建档（Cookie 会话）→ 路径生成 → 学习页协同生成 → 资源页阅读/作答/反馈 → 路径节点建议。前端三个工作台（`web/src/components/learning-path-workbench.tsx`、`learning-workbench.tsx`、`resource-workbench.tsx`）受前端保护原则约束，只做局部增强。

- 数据资产：PostgreSQL 16 + pgvector 持久化 20 组业务表、MetroPT-3 时序、AI4I 表格和知识卡索引。
- 测试基线：27 个测试文件、204 项 Vitest 用例通过；根项目 lint、类型检查和前端生产构建通过。

### 1.2 当前边界与维护重点

| # | 当前边界 | 代码事实 | 维护口径 |
|---|------|------|---------|
| B1 | 正式资源只有四类 | `src/learning/types.ts` 的 `LearningResourceType` 与生成器均只接受 `lecture`、`presentation`、`tiered_quiz`、`concept_map` | 提交材料、评测和界面统一使用四类口径 |

- 不恢复通用 `/api/sessions/*`、WebSocket、通用聊天；不展示模型隐式思维链。
- 不做多租户、复杂权限、无关平台功能；不引入 v1/v2 双实现或临时文件。

## 3. API 契约（新增/变更）

所有接口从 HttpOnly Cookie 会话推导 `learnerId`；请求体、队列消息、URL 中的用户标识一律不作为授权依据。未登录一律 401。

| 方法与路径 | 语义 | 备注 |
|---|---|---|
| `POST /api/learning/runs` | 创建协同学习运行 | 返回 `202 { runId }`；重复请求（同 idempotency key）返回已有 runId |
| `GET /api/learning/runs/:runId` | 运行快照：DAG、节点状态、最终资产 | 非本 learner 的 runId → 404 |
| `GET /api/learning/runs/:runId/events` | SSE 增量事件 | 支持 `Last-Event-ID` 续传；事件 id = run 内单调 `seq` |
| `POST /api/learning/runs/:runId/cancel` | 取消未结束运行 | 幂等；已结束返回当前终态 |
| `GET /api/learning/diagnostic` | 获取 12 道诊断题 | 首次建档后进入；题集固定 |
| `POST /api/learning/diagnostic-attempts` | 提交一次完整诊断 | 写 BKT 状态更新事件与诊断快照 |
| `GET /api/learning/profile` | 画像（扩展） | 增加知识掌握度/置信度、盲区、难度匹配曲线 |
| `GET /api/learning/runs/:runId/export` | 导出比赛证据包 | JSON：画像+诊断+DAG 事件+结论+EvidencePack+资源+反馈+画像变化 |
| 既有反馈/作答接口 | 保留 | 作答与反馈额外写入 BKT 更新事件 |
| `POST /api/learning/study/chat` | **删除** | 前端切换到 runs API 后同批删除，不长期双入口 |

## 4. 运行事件协议与 DAG 执行

### 4.1 核心类型（`server/runs/protocol.ts`）

```ts
interface StudyRunRequest {
  task: string;
  pathNodeId: string | null;
  resourceType: LearningResourceType;            // 四类正式资源
  collaborationMode: 'auto' | 'custom';
  selectedAgentIds: LearningAgentId[];           // custom 模式的真实约束（修 D1）
  temporaryReference?: { name: string; content: string } | null;
}

interface RunNodeSpec {
  key: string;                    // 稳定节点键，如 'retrieve.document'
  role: LearningAgentId;          // 六职责角色之一
  title: string;
  dependsOn: string[];
  mandatory: boolean;             // true = 门禁/不可跳过
  retryLimit: 2;                  // 失败最多重试 2 次
  timeoutMs: number;
}

interface StudyRunPlan {
  runId: string;
  nodes: RunNodeSpec[];
  gates: string[];                // 至少包含 'audit.claims' 与 'privacy.compliance'
  riskLevel: 'low' | 'medium' | 'high';
  revisionBudget: 2;              // 最多修订 2 次
}

interface RunEvent {
  seq: number;                    // run 内单调递增，SSE id
  runId: string;
  nodeKey: string | null;
  type: 'run.accepted' | 'node.started' | 'node.progress'
      | 'node.succeeded' | 'node.failed' | 'node.retrying'
      | 'run.revision' | 'run.cancelled' | 'run.succeeded' | 'run.failed';
  summary: string;                // 面向用户的公开摘要，不含思维链
  payload?: Record<string, unknown>;  // 证据/结论引用等结构化公开数据
  createdAt: string;              // ISO 时间戳
}
```

### 4.2 持久化

- `study_runs`：runId、learnerId、请求、计划 JSON、状态（`queued/running/succeeded/failed/cancelled`）、修订轮次、创建/结束时间。
- `study_run_nodes`：runId、nodeKey、attempt、状态、开始/结束时间、结果摘要、失败原因。
- `run_events`：`(run_id, seq)` 唯一，`seq` 由服务端在同一事务内 `coalesce(max(seq),0)+1` 分配；SSE `Last-Event-ID` 直接映射 seq 续传。

### 4.3 BullMQ 执行（`server/worker.ts` + `runs/executor.ts`）

- 队列 `study-run`，每个 DAG 节点一个 job：`jobId = ${runId}:${nodeKey}:${attempt}` —— BullMQ 按 jobId 去重，天然幂等；重复提交同一节点不会重复执行（修 D3 的重复请求问题）。
- job 数据只带 `{ runId, nodeKey, learnerIdHint }`；执行时从 PostgreSQL 读任务与计划，**learnerId 以数据库记录为准**（队列消息不做授权依据）。
- 失败：BullMQ `attempts: 3`（首次 + 重试 2 次），指数退避；超限置节点 `failed`，下游节点跳过，run 终态 `failed`。
- 取消：cancel 接口置 DB 状态 + `job.discard()`；节点执行器每步前检查取消标志。
- 断点恢复：worker 重启后，`running` 状态且节点未完成的 job 因 jobId 幂等可安全重投；PostgreSQL 中节点状态是唯一事实。
- Redis 只分发事件：节点执行器追加 `run_events`（事务内），同时 `PUBLISH run:{runId}`；SSE 订阅桥把事件推给前端，断线用 `Last-Event-ID` 从 PostgreSQL 回放缺口。

### 4.4 SSE 帧格式

```
id: <seq>
event: <type>
data: {"runId":"...","nodeKey":"retrieve.document","summary":"...","payload":{...}}
```

## 5. 动态 DAG 编排器（`runs/planner.ts`，纯函数）

输入：`StudyRunRequest` + 画像不确定度 + 知识风险 + 证据覆盖预估。输出：`StudyRunPlan`。

### 5.1 角色与节点

固定六个职责角色（与现有 `LEARNING_AGENT_IDS` 对齐）：`learning_planning`（学情建模）、`evidence_retrieval`（证据检索）、`domain_expert`（领域分析）、`resource_generation`（资源生成）、`cross_validation`（审核/裁决门禁）、`privacy_compliance`（合规门禁）。反方质询（debate）与证据裁决（adjudicate）由 `cross_validation` 角色以两个门禁节点承担。

### 5.2 编排规则（确定性，可单测）

```
节点全集：
  assess.learner          (learning_planning)
  retrieve.structured     (evidence_retrieval)   ← SQL 结构化检索
  retrieve.document       (evidence_retrieval)   ← FTS/向量文档检索
  analyze.domain          (domain_expert)        ← depends: retrieve.*
  generate.resource       (resource_generation)  ← depends: analyze.domain, assess.learner
  audit.claims            (cross_validation)  [mandatory] ← depends: generate.resource（Claim 裁决）
  debate.challenge        (cross_validation)  [mandatory 当含可核验事实] ← depends: audit.claims
  adjudicate.verdict      (cross_validation)  [mandatory] ← depends: debate.challenge，产出 supported/partial/conflict/unsupported
  privacy.compliance      (privacy_compliance)[mandatory]
  finalize.publish        (orchestrator 收尾)                    ← depends: adjudicate/privacy
依赖：retrieve.structured ∥ retrieve.document ∥ assess.learner 可并发。
```

- `auto`：按资源类型裁剪——`concept_map`/`review_cards` 不含 LLM 正文节点，但仍走完整门禁链；画像不确定度高（任一知识点 confidence < 0.5）→ 增加一轮 `debate.challenge` 复核难度适配；知识风险高（作答错误率 > 0.5）→ `adjudicate` 从严（partial 视为不通过）。
- `custom`：`selectedAgentIds` **真实裁剪**可选节点——未选中的角色其非门禁节点被移除（如未选 `learning_planning` → 无 `assess.learner`，学情输入退化为确定性快照）；`audit.claims`、`privacy.compliance` 两门禁任何情况下不可移除（修 D1，同时保留门禁）。
- 修订环：`adjudicate` 结论非 `supported` 时，`generate.resource` 以 revisionBudget 重新入队（带 failedClaims），最多 2 次；仍不合格 → 资源标记 `manual_review_required`（历史兼容状态名），禁止入库发布，保留完整追溯记录；后续任务由智能体补充检索与重生成，普通学习者无需审核资料。
- 一次运行至少执行 3 个业务角色（由依赖链保证）。

## 6. 数据模型

### 6.1 九组 PostgreSQL 领域表（`server/db/schema.ts`）

所有学习数据表必须含 `learner_id` 并执行服务层隔离（查询一律带 `where learner_id = session.learnerId`）。临时上传只存哈希、大小、有效期与审计结论，正文不落库。

| 组 | 表（要点） |
|---|---|
| 1 身份与会话 | `users`、`auth_sessions`（token_hash 唯一、过期）、`learner_onboarding`（角色/基础/目标/周时长/自述——仅作先验） |
| 2 画像与诊断 | `learner_profile_snapshots`；`diagnostic_questions`（12 题，知识点、L1-3、选项、答案、解析）；`diagnostic_sessions`（先验快照、状态、结论 JSON）；`diagnostic_answers`（session、题、作答、对错、耗时） |
| 3 知识状态与路径 | `learner_skill_states`（BKT：`p_mastery, p_guess, p_slip, p_learn, confidence`，来源枚举）；`bkt_updates`（每次状态变更的审计：事件类型、前后值、依据）；`learning_path_nodes/edges/items`（沿用现语义） |
| 4 资源与反馈 | `learning_assets`（含 difficulty、target_success_rate、难度依据 JSON）；`learning_asset_feedback`、`learning_asset_page_notes`、`learning_quiz_attempts`；`learning_chat_messages`、`learning_events` |
| 5 领域知识与向量 | `datasets`、`dataset_fields`、`dataset_rows`、`metro_readings`、`metro_event_windows`；`document_chunks` + `embedding vector(1024)` + `tsv tsvector`（生成列）+ GIN/GiST 索引 |
| 6 EvidencePack | `evidence_items`、`evidence_packs`、`evidence_pack_items`、`privacy_audit_events`（沿用现语义，平移到 PG） |
| 7 运行 DAG 与事件 | `study_runs`、`study_run_nodes`、`run_events`（§4.2） |
| 8 辩论与声明图 | `claims`（资源、文本、裁决、批评、事实分）；`claim_evidence`（边：support_level）；`debate_issues`（反方质询议题：无证据/冲突/越界因果/难度不适配）；`audit_decisions`（裁决记录：轮次、结论、依据、是否放行） |
| 9 评测报告 | `evaluation_cases`（60 案例：画像、任务、必备知识点、目标难度区间、允许证据、预期结构）；`evaluation_results`（案例、运行引用、幻觉率/难度适配/覆盖率明细） |

### 6.2 迁移管理

- `drizzle-kit generate` 产出 SQL 迁移文件（入库、可评审），`drizzle-kit migrate` 在部署/启动前执行；`CREATE EXTENSION IF NOT EXISTS vector` 放在初始迁移前的 compose init 脚本中。
- 枚举以 text + CHECK 约束表达（避免 PG 枚举类型的迁移负担）。

### 6.3 数据导入与启动

PostgreSQL 是唯一运行数据源。`pnpm db:migrate` 应用结构迁移，`pnpm db:bootstrap` 幂等导入知识卡、AI4I 与字段目录；`pnpm data:metropt` 下载官方 CSV，后端启动时通过流式导入写入 `metro_readings`。空数据或缺失 CSV 时只提示安装状态，**绝不生成伪时序数据**。

## 7. 个性化算法（全部纯函数 + 可审计落库）

### 7.1 BKT 知识状态追踪（`src/learning/bkt.ts`）

每知识点维护：`p_mastery`（掌握概率）、`p_guess`（猜测率）、`p_slip`（失误率）、`p_learn`（学习转移率）、`confidence`（数据量/一致性导出）。标准更新：

```
观测 correct:  P(L|+) = pM*(1-s) / (pM*(1-s) + (1-pM)*g)
观测 wrong:    P(L|-) = pM*s     / (pM*s     + (1-pM)*(1-g))
学习转移:      P(L')  = P(L|·) + (1 - P(L|·)) * t
confidence = f(尝试次数, 与历史一致性)，单调递增有上界
```

- 触发源：诊断作答、资源习题判分、讲义掌握反馈、任务完成。每次更新写 `bkt_updates`（前后值+触发事件），可审计。
- 自述/学历只作诊断先验（`p_mastery` 初值与题序），不得直接写为掌握度（修 D5）。

### 7.2 难度校准（`src/learning/difficulty.ts`）

```
readiness  = 0.6*p_mastery + 0.25*prereqReadiness + 0.15*confidence
targetDifficulty = clamp01( (readiness - p*) / (readiness - scaffold) )，p* ∈ [0.65, 0.80] 取 0.72
预计成功率 p̂ = readiness + (scaffold - readiness) * targetDifficulty，须落在 [0.65, 0.80]
scaffold = 脚手架强度（讲义高、习题中、挑战任务低）
```

- 输出 `DifficultyCalibration { targetDifficulty, expectedSuccessRate, rationale[] }` 随资源入库；实际作答正确率回流校准（替换硬编码 0.42，修 D2）。
- 先修缺口：按路径边计算未掌握先修比例，未修先修 → 降低难度并注入先修补强块。

### 7.3 初始诊断（`src/learning/diagnostic.ts`）

- 12 道固定题：Python（3）、数据处理/pandas（3）、统计（2）、时序（2）、设备诊断（2），各带知识点、L1-L3、解析与证据引用。
- 建档后引导完成；作答驱动 BKT 初始状态；未完成诊断时画像标注“未校准”，资源按保守难度生成。

### 7.4 苏格拉底提问（`src/learning/socratic.ts`）

- 选题：路径关键（处于当前活跃路径的前置闭包内）× 掌握置信度最低，优先级 = criticality * (1 - confidence)。
- 每轮只问一个问题；回答驱动 BKT 更新；终止条件：目标知识点 confidence ≥ 0.80 或完成 5 轮，随后生成资源。
- 问题与回答落 `learning_chat_messages`（surface=diagnostic）与 BKT 事件。

### 7.5 混合检索（`src/learning/retrieval/hybrid.ts`）

- 文档侧：`tsv @@ plainto_tsquery` + `embedding <=> query_vec`（cosine）双路召回各 top-20；RRF 合并：`score = Σ 1/(60 + rank_i)`，取 top-8 进 EvidencePack，保留 `document_chunks` 定位（source_id/页码）。
- 结构化侧不变：SQL 精确查询代表性数据行（故障正样本+正常行）。
- 嵌入：`text-embedding-v4`，1024 维，批量化 + 失败降级为纯 FTS（不阻塞资源生成）。

#### 7.5.1 可选 Web 补全（`server/search/searxng.ts`）

- SearXNG 通过 Docker `search` profile 在 `127.0.0.1:8088` 运行，默认关闭；PostgreSQL 仍是唯一业务数据源，SearXNG 不持久化训练数据或业务状态。
- 触发顺序固定为：SQL/本地文档混合检索完成后，若本地文档证据偏少（默认覆盖阈值 0.58）、任务涉及近期/标准/文献资料，或 Claim 反证复核明确要求补充来源，才调用 `/search?format=json`。
- 仅规范化标题、摘要、URL、引擎名与发布日期为 `source_type=web_search`、`retrieval_method=web` 的临时线索；不抓取网页正文、不做网页向量化。网络证据可信度为 low，不能将“结构化数据 + 网络摘要”标记为已交叉验证。
- API Key、邮箱、手机号码、身份证号等检索词由 Web 查询门禁直接阻断；服务 403/超时/网络错误只记录降级原因，主链继续使用 PostgreSQL EvidencePack。

### 7.6 四类资源统一契约

讲义、PPT、分层习题（L1/L2/L3，带答案/解析/难度/证据引用）和知识脉络（Mermaid 渲染）统一走 `generate.resource → audit.claims → debate → adjudicate → privacy` 门禁；结构校验器保证入库契约一致。

### 8.2 量化评测（`pnpm evaluate`，`scripts/evaluate.ts`）

- 60 个固定 `EvaluationCase`（三画像各 20），覆盖 AI4I、MetroPT-3、四类正式资源、基础/进阶/迁移三层任务。
- 指标（`evaluation_results` 落库，报告 JSON 输出）：
  - 幻觉率 = unsupported 事实声明 / 可审计事实声明，**< 5%**
  - 难度适配准确率 = 难度区间∩脚手架∩画像全匹配案例 / 总案例，**≥ 85%**
  - 核心知识覆盖率 = 有证据支持的必备知识点 / 黄金知识点，**≥ 90%**
- 自动跑 60 案例；12 个分层样本与全部失败案例执行离线回放、规则门禁和可追溯记录核验。任一阈值未达 → 不标记完成，回到对应任务修复。

### 8.3 证据包导出（`GET /api/learning/runs/:runId/export`）

单文件 JSON：初始画像 → 诊断作答 → DAG 节点事件 → 各 Agent 结论 → EvidencePack → Claim/质询/裁决 → 最终资源 → 学习反馈 → 画像变化。三账号各出一份，作为“差异化学习者初始学情数据源”提交物。
