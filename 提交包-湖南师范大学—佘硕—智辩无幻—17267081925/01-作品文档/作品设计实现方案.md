# 作品设计实现方案

> IM-Training-Agent：面向"设备数据分析与故障诊断"垂直领域的个性化训练与多智能体可信协同系统。
> 本文档是唯一主方案文档，覆盖赛题要求的方案说明，并整合协同协议、幻觉治理、数据合规与领域迁移说明。

## 1. 问题定义

垂直领域技能训练中大模型面临一个核心矛盾：**个性化越强，内容越可能失真；约束越强，资源越可能千人一面**。单一模型直接生成既无法保证专业事实（字段含义、数据数值、故障因果）与行业证据一致，也无法随学习者状态调整难度与脚手架。

本作品的技术主张：

> 学情图决定怎么教，声明证据图约束教什么，协同运行链记录为何这样决策；个性化可以变化，专业事实不可漂移。

## 2. 技术方法：双图一链 + VACP 可验证协同协议

### 2.1 学情图——决定怎么教

- 节点为知识点，边为先修/分支/应用/复习关系；节点状态由 BKT（贝叶斯知识追踪）维护：掌握概率、猜测率、失误率、学习转移率、置信度。
- 每次诊断作答、习题判分、讲义掌握反馈、启发式追问都会更新 BKT 并写入 `bkt_updates` 审计行（前后值 + 触发事件）。
- 资源难度由难度校准模型推导：`readiness = 0.6×掌握 + 0.25×先修就绪 + 0.15×置信度`，预计成功率收敛到 65%–80% 教学区间。
- 反馈后下一步动作由决策纯函数给出（补强/继续/进阶/先追问）并持久化到 `learning_decisions`（含 BKT 前后值与理由）；路径节点建议优先消费决策记录，下一次运行可引用来源决策，形成"反馈 → 决策 → 下一运行"的闭环。

### 2.2 声明证据图——约束教什么

- 资源草稿被拆解为原子事实声明（Claim），按类型分为：数值、字段含义、方法步骤、因果判断、风险建议、非事实教学表达（`non_factual` 不入幻觉率分母）。
- 每条 Claim 绑定证据边，证据来自结构化数据查询（SQL 抽样故障正样本与正常行，带行号/时间窗定位）与文档混合检索（PG 全文 + pgvector 向量，RRF 融合，带来源/页码定位）。
- 声明生命周期：`drafted → extracted → evidence_linked → challenged → adjudicated → revised / released / manual_review`；跨修订轮以 `logical_key` 聚组、`supersedes_claim_id` 串联，可从终稿回溯初稿。

### 2.3 协同运行链——记录为何这样决策

一次协同 = 一个 StudyRun 动态 DAG（BullMQ 持久化，worker 并发 4）：

```
学情建模 → 双路并行检索 → 领域分析 → 资源生成
  → Claim 审核 → 反方质询 → 证据裁决 → 隐私合规 → 发布收尾
```

全部运行事件带单调 seq（SSE 断线 Last-Event-ID 续传）；每个节点成功前先持久化**不可变产物（artifact）**，发布收尾固化执行清单散列（manifest hash）。

## 3. 可信协同协议（VACP）

**原则**：节点间通过产物 ID 引用协作；产物不可变（修订轮 attempt+1 新产物不覆盖旧产物）；内容散列对递归排序的稳定 JSON 计算 SHA-256，离线可重算；**门禁只紧不松**；fail closed（无审核产物不发布、有 unsupported 不发布、引用越界不发布、修订预算用尽则自动拒绝发布并固化发布决定与收尾快照，保证审计链完整）。普通学习者不承担资料审核职责。

**角色与执行者分离**：六个业务角色（学情建模/证据检索/领域分析/资源生成/审核裁决/隐私合规）用于权限与用户选择；十个执行者 actor 区分真实职责——`learner_modeler`、`structured_retriever`、`document_retriever`、`domain_analyst`、`resource_author`、`claim_auditor`、`red_team_critic`、`evidence_judge`、`privacy_guard`、`publisher`。每个节点产物记录：输入引用、公开结论（observations / basisRefs / decision / uncertainty / nextAction）、生产者元数据（模型、promptHash、settingsHash）。一次运行至少 3 个业务角色；custom 模式真实裁剪业务节点，五道门禁节点（审核/质询/裁决/隐私/发布）不可移除。

**两阶段策略决策**：① 运行前从目标知识点与先修闭包的真实 BKT 推导画像不确定度、知识风险与任务事实风险，决定风险等级与质询重点；② 检索后按实际证据产物修正——证据为空或覆盖低则禁止强事实表达、数据与文档冲突则裁决从严、任务事实风险高则启用数值核验与越界因果规则、学情置信度低则增加难度质询。任何分支不减少门禁。

## 4. 幻觉治理与知识溯源

**确定性核验**（纯函数，结论只能比基础审核更严）：数值逐个与绑定证据比对；字段含义对数据集字段字典核对；越界因果拦截（"一定会/必然导致"且无限定词 → unsupported）；引用越界检查。审核 Agent 不可用时规则门禁照常生效。

**独立质询与裁决**：批评 Agent 只读草稿、声明与证据（不读生成端理由），可发起反证检索——只在已有知识库与数据中执行、不联网，命中并入证据包供修订引用，未命中如实记录；裁决 Agent 只读结构化声明案件，判决与规则结论**取更严格者**；即使共用同一底层模型，系统提示、输入包与产物记录相互独立（promptHash/settingsHash 落库可核验）。

**修订链**：未放行轮次把失败声明回传生成端，修订轮产出新草稿与新声明集并自动建立替代关系。实测：一次运行三轮修订中 unsupported 声明 3→2→1 收敛；三画像提交数据包中 maintenance 案例初稿幻觉率 25% → 终稿 0%（门禁净增益 25 个百分点），离线回放与在线裁决完全一致。

**知识溯源**：资源内容块绑定知识点与证据 ID；验证页"声明证据表"可从任一终稿声明回溯初稿原文 → 每轮质询 → 每轮裁决 → 证据定位；篡改产物、删除证据边、放松裁决均会被离线校验发现（`pnpm verify:export` / `pnpm replay:run`）。

**故障注入测试**：错数字、越界因果、字段含义写错、引用越界、无证据建议、核验只严不松等 11 个固定 fixture 用例（`src/learning/claim-verification.test.ts`），全部通过。

## 5. 数据合规与隐私

- 登录会话使用 HttpOnly Cookie，`learnerId` 一律由服务端会话推导；**URL、请求体、队列消息中的用户标识不作为授权依据**；所有学习数据按账号隔离，跨账号访问 404（有隔离测试）。
- 用户上传资料默认**仅作当前任务临时参考**：正文在隐私节点完成后从运行请求中抹除，不进个人画像；用户明确同意后，服务端策展智能体先做敏感信息阻断，再按相关性、质量、重复风险门禁决定是否写入版本化知识来源。普通学习者不承担资料审核职责，隐私合规为每次运行强制门禁节点。
- 证据包导出前脱敏：移除密码/Cookie/API Key/上传正文；导出校验器内置敏感字段扫描（password/apiKey/secret/cookie/token），发现即失败。
- **模型隐式思维链永不展示、永不保存、永不导出**；产物只存公开结论。
- API Key 仅存本机 `.env`（被 Git 忽略）；演示数据全部为公开许可数据集（AI4I 2020 / MetroPT-3 CC BY 4.0 / 官方文档），出处随数据登记。

## 6. 领域可迁移性

"换数据不换架构"：领域特有内容全部在数据层，协议/门禁/产物/验证/评测体系对领域无假设。新增一个垂直领域 = **一份 CSV（声明式导入 + SHA256 校验）+ 一组知识卡（frontmatter Markdown 自动切块入库）+ 检索别名 + 诊断题与黄金集更新**；编排器、门禁、产物层、验证页、离线校验、BKT/难度/决策纯函数、评测与消融脚本全部复用。本项目本身即先例：AI4I（入门表格数据）与 MetroPT-3（152 万行时序）两域共存于同一证据层，前端与协议零改动。

## 7. 系统架构与实现

```
[web :3000 Next.js 四工作台：路径/学习/资源/验证]
            │ HTTP / SSE
[api :3001 Express]  ──▶ [worker BullMQ：DAG 节点执行]
            │                    │
[PostgreSQL 16 + pgvector] [Redis 7：队列/锁/事件分发]
  唯一业务数据源              不持久化业务状态
```

- 数据层：30+ 张领域表（Drizzle 迁移 0000–0010），MetroPT-3 时序 1,516,948 行 + AI4I 1 万行 + 官方文档知识切片 616 条（含 1024 维向量）。
- 模型层：OpenAI-compatible 多模型路由（`server/prompts.ts` 集中管理全部系统提示词）。当前默认执行模型为 MiMo-v2.5（OpenCode Zen 网关），可切换通义千问 `qwen-plus`（DashScope）；嵌入模型 `text-embedding-v4`。每个智能体角色可独立指定模型与思考深度，路由与参数散列写入产物元数据（promptHash/settingsHash 可核验）。
- 个性化资源形态：讲义（3000 字级图文 + 可运行代码 + 数据摘录表）、PPT 演示稿（要点页 + 讲解词）、分层习题（选择/填空/简答三题型 9–12 道，L1–L3）、知识脉络（Mermaid 关系图 + 逐节点解读 + 阅读路径）。
- 关键模块索引：`server/prompts.ts`（提示词唯一事实源）、`server/runs/`（planner/executor/artifacts/policy/metrics/claim-trace/snapshots/service/routes）、`src/learning/`（bkt/difficulty/diagnostic/audit/claim-verification/decision/evaluation/socratic/quiz/retrieval）、`scripts/`（evaluate/ablation/verify-run-export/replay-run/demo-seed）。
