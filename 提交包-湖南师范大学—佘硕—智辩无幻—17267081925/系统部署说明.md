# 《智辩无幻》系统部署说明

Docker 运行 PostgreSQL / Redis，pnpm 启动 API、Worker 与 Web。AI4I 与领域知识库可支撑完整主链演示；MetroPT-3 完整时序数据按需下载。

## 1. 环境要求

| 项目 | 版本 / 说明 |
|---|---|
| Node.js | 18 或更高版本 |
| pnpm | 已随 `pnpm-lock.yaml` 锁定依赖 |
| Docker Desktop | 用于 PostgreSQL 16 + pgvector、Redis 7 |
| 网络 | 首次安装依赖和需要调用模型时需要；离线测试无需模型调用 |

以源码包中的 `.env.example` 创建本地 `.env`，并填写模型服务密钥。

## 2. 首次部署

在 `im-training-agent-源码.zip` 解压后的根目录执行：

```powershell
pnpm install
Copy-Item .env.example .env
docker compose up -d postgres redis
pnpm db:migrate
pnpm db:bootstrap
pnpm demo:seed
```

`.env` 至少需要配置：

```text
DASHSCOPE_API_KEY=你的模型服务密钥
DATABASE_URL=postgres://im_training:im_training_dev@localhost:5432/im_training
REDIS_URL=redis://localhost:6379
```

如果 5432 或 6379 被占用，请同时修改 `POSTGRES_PORT` / `REDIS_PORT` 与 `DATABASE_URL` / `REDIS_URL`，并重新执行 `docker compose up -d postgres redis`。不要修改容器内端口。可用以下命令确认基础设施：

```powershell
docker compose ps
```

## 3. 启动系统

打开三个终端窗口，在源码根目录分别执行：

```powershell
pnpm server        # API: http://localhost:3001
pnpm worker        # BullMQ 协同 DAG Worker
pnpm --dir web dev # Web: http://localhost:3000
```

访问 `http://localhost:3000`，使用 `pnpm demo:seed` 创建的演示账号进入系统。建议演示顺序：画像 → 路径 → 学习 → 资源 → 验证。

## 4. 数据准备说明

| 数据 | 是否随源码包提供 | 用途 |
|---|---|---|
| AI4I 2020 CSV | 是 | 设备故障标签、字段和统计训练 |
| 知识库 Markdown 切片 | 是 | 文档检索、证据定位、教学解释 |
| 三组画像运行导出 | 是（`05-测试数据/`） | 数据核验与门禁回放 |
| MetroPT-3 完整 CSV | 否，可选 | 大规模时序演示；按需下载 |

### 4.1 初始化后的演示数据库

依次执行 `pnpm db:migrate`、`pnpm db:bootstrap` 和 `pnpm demo:seed` 后，系统会建立完整表结构，导入 AI4I、领域知识切片与数据集元信息，并创建零基础、进阶、在职运维转岗三类演示账号及其初始学情和学习路径。这套可重复构建的演示基线足以完成画像、路径、学习、资源、验证的全流程展示。

新环境从公开演示基线开始运行；三组可独立核验的完整运行记录位于 `05-测试数据/差异化画像数据包/`。

若需要完整 MetroPT-3 数据，执行：

```powershell
pnpm data:metropt
pnpm db:bootstrap
```

下载脚本会校验官方压缩包 SHA-256。没有完整 MetroPT-3 CSV 时，系统仍可使用 AI4I、已导入知识切片与现有公开摘要运行，不会伪造时序数据。

## 5. 验收与测试

```powershell
pnpm test
pnpm typecheck
pnpm --dir web build
pnpm evaluate
pnpm ablation
```

验证基线：`pnpm test` 为 **27 个测试文件 / 204 项通过**；`pnpm evaluate` 为 60/60 离线案例通过；`pnpm ablation` 三项消融通过。三组固定真实运行数据的散列和门禁可按《单元测试说明》所列命令独立复算。

## 6. 常见问题

| 现象 | 处理方式 |
|---|---|
| API 或 Worker 连不上数据库 | 检查 `.env` 中的 `DATABASE_URL` 是否与 `POSTGRES_PORT` 一致，再执行 `docker compose ps` |
| Redis 连接失败 | 检查 `REDIS_URL` 是否与 `REDIS_PORT` 一致；确认 Redis 容器处于 healthy |
| 任务长期处于运行中 | 确认 `pnpm worker` 正在运行；修改 Worker 代码后需重启 Worker |
| 模型调用失败 | 检查 `.env` 中密钥与模型服务地址；设置页可确认当前路由是否可用 |
| 前端构建时访问字体失败 | 项目使用系统字体栈；不要额外添加在线字体依赖 |
| 全量 live 评测未执行 | 默认评测为离线；live 调用会消耗模型额度，需取得授权后显式运行 |

## 7. 安全边界

- 源码包提供 `.env.example`，部署密钥在本地配置；
- 用户上传资料默认仅用于当前任务，未经明确同意与隐私门禁不会进入知识库；
- 导出包不包含模型隐式思维链，且可用 `pnpm verify:export` 扫描敏感字段。
