# 测试数据集说明

本文档介绍 IM-Training-Agent 系统使用的测试数据集，包括数据来源、规模、特征和使用方式。

## 数据集概览

| 数据集名称 | 类型 | 规模 | 用途 | 来源 |
|-----------|------|------|------|------|
| MetroPT-3 | 时序传感器数据 | 1.5万条记录 | 压缩机故障诊断的结构化证据 | Kaggle |
| AI4I 2020 | 预测性维护数据 | 1万条记录 | 设备质量预测的补充证据 | UCI Machine Learning |
| 知识卡片库 | 领域知识文档 | 208张卡片 | 压缩机诊断理论知识 | 人工整理 |
| 差异化学习者画像 | 学习者档案 | 2组典型画像 | 个性化路径生成测试 | 合成数据 |

## 1. MetroPT-3 数据集

### 1.1 数据说明

**来源**：Kaggle - MetroPT-3 Dataset  
**描述**：葡萄牙地铁空气生产单元（APU）压缩机的传感器时序数据  
**时间跨度**：2020年1月-2021年12月  
**采样频率**：每小时一次  

### 1.2 数据规模

- **总记录数**：15,034 条
- **设备数量**：3 台压缩机（TP2, TP3, TP4）
- **传感器维度**：22 个传感器通道
- **故障标签**：包含已知故障事件标注

### 1.3 传感器字段

| 传感器代码 | 含义 | 单位 | 正常范围 |
|-----------|------|------|---------|
| `TP2` | 压缩机2油温 | °C | 60-80 |
| `TP3` | 压缩机3油温 | °C | 60-80 |
| `H1` | 湿度传感器1 | % | 30-70 |
| `DV_pressure` | 放气阀压力 | bar | 8-10 |
| `Reservoirs` | 储气罐压力 | bar | 9-11 |
| `Oil_temperature` | 油温 | °C | 50-70 |
| `Motor_current` | 电机电流 | A | 10-30 |
| `COMP` | 压缩机状态 | 布尔 | 0/1 |
| ... | （共22个字段） | - | - |

### 1.4 在系统中的作用

- **证据检索**：当学习者询问"压缩机油温过高的典型特征"时，系统从 MetroPT-3 检索相关时序记录
- **习题生成**：基于真实故障案例生成诊断题目
- **交叉验证**：验证生成内容是否与真实数据一致

### 1.5 数据样例

```csv
timestamp,TP2,TP3,H1,DV_pressure,Reservoirs,Oil_temperature,Motor_current,COMP
2020-01-01 00:00:00,72.3,68.5,45.2,8.9,9.5,65.8,18.4,1
2020-01-01 01:00:00,73.1,69.2,46.1,8.8,9.4,66.2,19.1,1
2020-01-01 02:00:00,89.5,88.3,48.7,7.2,8.1,82.6,28.9,1  # 异常：油温过高
```

## 2. AI4I 2020 数据集

### 2.1 数据说明

**来源**：UCI Machine Learning Repository  
**描述**：工业4.0场景下的预测性维护数据集  
**特征**：设备运行参数与故障类型的关联  

### 2.2 数据规模

- **总记录数**：10,000 条
- **特征数量**：14 个特征（6个传感器 + 8个派生指标）
- **故障类型**：5 种（工具磨损、散热不足、功率故障、过应变、随机故障）
- **故障率**：约 3.4%（339 条故障记录）

### 2.3 特征字段

| 字段名 | 说明 | 示例值 |
|--------|------|--------|
| `Type` | 产品质量类型 | L/M/H（低/中/高）|
| `Air_temperature` | 环境温度 | 298.1 K |
| `Process_temperature` | 加工温度 | 308.6 K |
| `Rotational_speed` | 转速 | 1551 rpm |
| `Torque` | 扭矩 | 42.8 Nm |
| `Tool_wear` | 刀具磨损 | 0-253 min |
| `Target` | 是否故障 | 0/1 |
| `Failure_Type` | 故障类型 | TWF/HDF/PWF/OSF/RNF |

### 2.4 在系统中的作用

- **补充证据**：当 MetroPT-3 数据不足时，从 AI4I 检索相似工况
- **对比学习**：生成"压缩机 vs 通用设备"的对比知识点
- **泛化能力**：测试系统在非压缩机场景下的表现

## 3. 知识卡片库

### 3.1 数据说明

**来源**：人工整理（基于压缩机维护手册、诊断文献）  
**格式**：Markdown 卡片  
**组织方式**：按知识点层级结构化  

### 3.2 数据规模

- **总卡片数**：208 张
- **覆盖主题**：
  - 压缩机原理（32张）
  - 故障诊断方法（58张）
  - 传感器技术（41张）
  - 维护规范（35张）
  - 案例分析（42张）

### 3.3 卡片结构

每张卡片包含以下字段：

```markdown
---
id: kp_001
title: 压缩机工作原理
category: 基础理论
difficulty: 0.3
prerequisites: []
---

## 核心概念

螺杆式压缩机通过一对相互啮合的转子，将气体从吸气端压缩并输送到排气端...

## 关键参数

- 排气压力：8-10 bar
- 油温范围：60-80°C
- 转速：1500-3000 rpm

## 常见误区

❌ **误区**：认为油温越低越好  
✅ **正确理解**：油温需要在60-80°C之间，过低会导致冷凝水积聚
```

### 3.4 在系统中的作用

- **文档证据**：补充 MetroPT-3 的理论背景
- **概念解释**：生成讲义时引用卡片内容
- **知识脉络**：构建知识点间的依赖关系

## 6. 数据集差异化价值

### 6.1 为什么需要三个数据源？

| 数据源 | 优势 | 局限 | 互补作用 |
|--------|------|------|---------|
| MetroPT-3 | 真实压缩机时序数据，故障标注准确 | 缺少理论解释 | 提供实证依据 |
| AI4I | 多设备类型，故障模式丰富 | 非压缩机专用 | 扩展泛化能力 |
| 知识卡片 | 理论完备，概念清晰 | 缺少实测数据 | 提供理论框架 |

### 6.2 混合检索策略

当生成"压缩机油温过高的诊断步骤"时：

1. **结构化证据检索**（MetroPT-3）：
   - 查询 `oil_temperature > 80` 的时序记录
   - 找到 127 条异常案例

2. **文档证据检索**（知识卡片）：
   - 向量搜索"油温过高 诊断"
   - 匹配到卡片 `kp_045: 油温异常诊断流程`

3. **RRF 融合**：
   - 结构化证据置信度：0.85
   - 文档证据置信度：0.78
   - 融合后总置信度：0.82

4. **交叉验证**：
   - 卡片：建议检查冷却系统
   - 时序数据：异常时刻 `Motor_current` 同步升高
   - ✅ 验证通过：两者吻合

## 8. 数据集更新与扩展

### 8.1 新增数据源接入流程

1. **数据格式转换**：将新数据转为 CSV 或 JSON
2. **编写导入脚本**：参考 `server/seed.ts`
3. **向量化嵌入**：调用 `text-embedding-v3` 生成向量
4. **索引构建**：创建 GiST 索引加速检索

### 8.2 数据质量监控

系统记录每次证据检索的命中率：

```sql
SELECT 
  dataset_name,
  AVG(confidence_score) AS avg_confidence,
  COUNT(*) AS usage_count
FROM evidence_retrieval_log
WHERE created_at > NOW() - INTERVAL '7 days'
GROUP BY dataset_name;
```

**健康指标**：
- 平均置信度 > 0.7
- 每日检索命中 > 100 次
- 交叉验证通过率 > 85%

## 10. 常见问题

### Q1: 为什么 MetroPT-3 只有 1.5 万条？

**A**: 1.5万条覆盖了2年的完整运行周期，包含所有典型故障模式。更多数据会增加检索延迟，且边际收益递减。

### Q2: 知识卡片如何保证准确性？

**A**: 卡片内容基于《压缩机维护手册》（西门子/阿特拉斯官方文档）和顶会论文，由领域专家人工审核。

### Q3: 如何测试不同领域的迁移能力？

**A**: 可替换 MetroPT-3 为其他设备数据（如泵、风机），测试系统的泛化性能。
