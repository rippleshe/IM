# 设备诊断资料首批下载清单（精简版）

> 本轮只收集一套“够用的核心资料”，不追求把网上所有数据集都搬回来。队员只负责下载和打包；清洗、去重、OCR、Markdown 化、切片、向量化和 PostgreSQL 入库由我统一处理。

## 队员只做这几件事

1. 优先下载“方法与培训”以及“核心设备资料”。
2. 每个页面优先保存 README、数据说明、字段说明和论文/讲义 PDF。
3. 不要把完整原始大数据包上传到数据库；链接标注“只看说明”时，不下载原始数据。
4. 不改原文件名、不改原始内容、不写清洗脚本、不操作数据库。
5. 最后把文件夹压缩成 `队员姓名_设备诊断资料.zip` 发给我。

## A. 方法与培训资料（本轮全部保留）

这些文件体积小、对智能体写讲义和解释诊断结果最有用，优先级最高。

- [NIST：PHM 在制造业中如何落地（PDF）](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=928501)：状态监测、诊断和预测性维护的工程框架。
- [NIST IR 8012（PDF）](https://nvlpubs.nist.gov/nistpubs/ir/2014/nist.ir.8012.pdf)：机器状态监测、诊断数据处理和展示指南。
- [NIST/ASME PHM 会议总结（PDF）](https://nvlpubs.nist.gov/nistpubs/ams/NIST.AMS.100-31.pdf)：制造业 PHM 的实施问题和实践经验。
- [FRICK 螺杆压缩机振动分析指南](https://docs.johnsoncontrols.com/industrialrefrigeration/r/FRICK/en-US/SGC/SGX-Rotary-Screw-Compressor-IOM-MK2/2019-07/2019-07/Maintenance/Vibration-Analysis)：压缩机测点、基线和误判风险。
- [Pump Vibration Analysis（Texas A&M）](https://oaktrust.library.tamu.edu/items/67ca6922-4f71-4cf1-9f78-77b72ea80246)：泵振动测量、频谱和故障排查。
- [OMRON Predictive Maintenance Guide（PDF）](https://www.ia.omron.com/data_pdf/cat/predictive_maintenance_n239-e1-01.pdf?id=3769)：设备状态监测和预测性维护案例。
- [Condition Monitoring for Predictive Maintenance（PDF）](https://diva-portal.org/smash/get/diva2:1950819/FULLTEXT02.pdf)：状态监测、故障检测、严重度和 RUL 教学材料。
- [Data Fusion Techniques for Fault Diagnosis（arXiv）](https://arxiv.org/abs/2211.09551)：多传感器数据融合方法。
- [Data-driven Machinery Fault Detection（arXiv）](https://arxiv.org/abs/2405.18843)：机器故障检测方法和常见问题。
- [Multi-Fault Diagnosis of Industrial Rotating Machines（arXiv）](https://arxiv.org/abs/2206.14153)：旋转机械多故障诊断方法。
- [Predictive Maintenance Literature Review（开放论文）](https://doi.org/10.1016/j.cie.2025.111193)：预测性维护的数据处理和评估框架。
- [工业设备故障诊断范围综述（arXiv）](https://arxiv.org/abs/2101.05451)：工业控制、汽车、航空设备诊断方法综述。

## B. 核心设备资料（只收必要内容）

- [MetroPT-3 论文（Scientific Data）](https://www.nature.com/articles/s41597-022-01877-3)：传感器、采集背景和故障事件。

- [Condition Monitoring of Hydraulic Systems（UCI）](https://archive.ics.uci.edu/dataset/447)：液压压力、流量、温度和振动说明；先下载 README/字段说明。

- [Paderborn University Bearing Data Center](https://mb.uni-paderborn.de/en/kat/research/bearing-datacenter)：保存 README、工况和损伤等级说明，不下载完整原始包。

- [XJTU-SY Bearing 数据说明（Markdown）](https://github.com/WangBiaoXJTU/xjtu-sy-bearing-datasets/blob/master/README.md)：保存 README 和字段/工况说明。

## C. 本轮暂不下载

下面资料不是不要，而是先不占用队员时间和磁盘：

- MIMII 这类 100 GB 级工业声音原始包；先不下载音频，只保留论文和 README。
- NASA IMS、FEMTO、C-MAPSS 等完整原始 ZIP；需要某个数据集时再单独安排一名队员。
- Bosch CNC、CFD-Datasets、PHM 挑战赛等扩展数据；等核心资料入库后再补。
- 已经在项目数据库中的 MetroPT-3 完整 CSV；不要重复下载。

```text
├─ 01_方法与培训/
├─ 02_压缩机与车辆气压/

```

压缩包交给我后，我会统一完成：校验 → 解压/OCR → 去重 → Markdown 化 → 来源定位 → 知识卡切片 → PostgreSQL 导入 → pgvector 向量回填 → 检索抽查。

## 数据库容量和入库边界

项目使用 **PostgreSQL 16 + pgvector**，不是 SQLite，也不是独立的向量数据库。原始 PDF、ZIP、音频和超大 CSV 不直接塞进 PostgreSQL；原文件保留在文件存储/暂存目录，数据库只保存：

- 数据集元数据、许可、校验值和字段说明；
- 清洗后的 Markdown/文本切片（`document_chunks`）；
- 与诊断直接相关的结构化样本或统计结果；
- 文本向量和检索索引。

截至本轮检查：数据库约 **398 MB**，其中 `metro_readings` 约 **355 MB**（已有 151.7 万行）；`document_chunks` 约 **9.4 MB**，已有 616 个切片。方法讲义和抽取后的设备说明可以正常放入；100 GB 级原始数据不能直接入库。

因此，本轮目标是“十几份高价值讲义 + 少量核心设备说明”，不是下载几十个完整数据集。这样队员今晚能完成，数据库也不会被无用原始文件撑大。
